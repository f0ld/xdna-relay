# T-016/T-017 — NPU prefill + KV handoff, two overlapping requests

Platform profile `performance` (AC for 1B runs, battery for the 3B run). IRON Llama (bf16,
NPU) → llama.cpp Vulkan (iGPU). Tools: `bench/handoff_probe.py`, `bench/hybrid_bench.py`.

## Handoff quality (346-token prompt; reference = llama.cpp prefilling itself)
| model → iGPU GGUF | K / V rel.err (max over 3 layers) | first-token KL | 64 greedy tokens | export+convert+import |
|---|---|---|---|---|
| 1B → BF16 | 1.4% / 3.6% | 4.9e-4 | identical | 2+20+1 ms (10.8 MiB) |
| 3B → BF16 | 2.1% / 5.0% | 3.3e-4 | identical | 15+60+2 ms (37.7 MiB) |
| 3B → Q4_K_M | 10% / 22% (Q4 computes its own KV) | 2.2e-2 | identical | 15+52+2 ms |
Unpermuted K: ~140% error (RoPE layout, see pitfalls.md).

Prefill time, 346 tokens: 1B iGPU-BF16 471 ms / NPU 475 ms; 3B iGPU-BF16 1203 ms,
iGPU-Q4 465 ms, NPU 1580 ms (~220 tok/s — IRON 3B prefill is a measured bottleneck).

## Two requests (1B BF16): A decodes 200 tokens; B (1494-token prompt) arrives 1 s later
| mode | A tok/s during B prefill | A tok/s overall | B TTFT | makespan |
|---|---|---|---|---|
| A alone | 29.2–30.6 | | | |
| B prefill on iGPU (2nd context) | 5.8–5.9 | 21.9–22.2 | 1.67–1.86 s | 9.1–9.3 s |
| B prefill on NPU, same process | 5.8–7.2 | 23.7–24.0 | 0.86–0.98 s | 8.4–8.5 s |
| B prefill on NPU worker process | **21.4–22.9** | 23.8–25.1 | 1.12–1.14 s | 8.0–8.5 s |

- Same-process NPU prefill starves the iGPU decode thread: IRON's host loop holds the GIL.
  A worker process fixes it (A −22% during B's prefill, as T-019's contention predicts).
- Worker-process TTFT includes IPC + a 48 MB shared-memory copy + blob build (~125–150 ms).

## 3B Q4_K_M, same scenario
First attempt (performance, battery): iGPU mode A 5.6 tok/s during B's prefill, B TTFT 1.96 s;
NPU worker mode failed — the 1493-row prompt chunk ran past the driver's default command
timeout (`ERT_CMD_STATE_TIMEOUT`, `aie2_set_cmd_timeout`). Operator then set
`options amdxdna tdr_timeout_ms=30000` (/etc/modprobe.d/amdxdna-tdr.conf) and reloaded.

Rerun 21:2x, platform profile `balanced`, on AC, B prompt 1494 tokens, A alone 35.0 tok/s:
| mode | A tok/s during B prefill | A tok/s overall | B TTFT | B tok/s | makespan | handoff |
|---|---|---|---|---|---|---|
| B prefill on iGPU | 5.0 / 7.3 | 24.1 / 24.2 | **1.79 / 1.93 s** | 16.6 / 16.9 | 8.37 / 8.35 s | — |
| B prefill on NPU worker | **28.4 / 28.4** | 29.3 / 29.1 | 5.85 / 5.74 s | 31.8 / 29.1 | **7.90 / 7.88 s** | 692 / 691 ms |

- A barely notices B (28.4 vs 35.0 alone) and the pair finishes ~6% sooner, but B waits
  3× longer: IRON's 3B prefill (~1493 tok in ~5 s, ~300 tok/s) is slower than the iGPU's Q4.
  On 3B the NPU path trades B's latency for A's throughput; the scheduler needs a policy
  (e.g. NPU only when B's deadline allows, or split B's prefill).
- Handoff convert+import is 690 ms here vs ~77 ms in handoff_probe (3B, 346 tokens, so
  ~330 ms expected for 1493 by size) — still ~2× too slow; open item.
