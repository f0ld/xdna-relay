# T-034 (M7): OpenAI-compatible server over the scheduler (2026-11-25)

`python -m xdna_relay.server` (src/xdna_relay/server/): slots = llama.cpp contexts on the
iGPU (optional draft per slot), one IRON NPU prefill worker (packed bfp16 for Qwen3), the
prefix cache, `PlacementPolicy` per request. `/v1/chat/completions`, `/v1/completions`
(SSE streaming), `/v1/models`, `/health`; greedy only; each response carries `x_relay`
(placement, reused tokens, TTFT, estimate). Tests: `scripts/test.sh T-034` 9/9.

## Two-request scenario through HTTP (`bench/server_load.py`, client-side timing)
Qwen3-8B (Q4_K_M on iGPU, HF bf16 packed on NPU), `--slots 2 --no-think`, preset
`qwen3-8b-packed`. Platform `balanced`, on AC, NPU pmode `performance`; no NPU TDR.
A streams 200 tokens; 1 s after A's first token, B (~1.7k-token prompt) arrives.

| server | A tok/s while B waits | A overall | B TTFT | B placed | A done | B done |
|---|---|---|---|---|---|---|
| `--placement igpu` | 1.8–2.7 | 9.7 | 5.57–6.03 s | iGPU | 20.7 s | 9.9–10.2 s |
| `--placement auto` | **10.2** | **12.0** | **4.71–4.91 s** | NPU (1716 tok) | **16.9 s** | **8.8–8.9 s** |

Same as the in-process benchmark (2026-11-25-packed-gemm.md): the HTTP layer adds nothing
measurable. With `auto`, A finishes 3.8 s (18%) sooner and B 1.1–1.3 s sooner.

## Notes
- Determinism: greedy outputs are identical for the same prefill path; a warm request that
  reuses a prefix can flip near-ties vs a cold one (T-027's batch-split effect).
- Slots are separate llama.cpp contexts (the model is loaded once per slot); decode is not
  batched across slots yet.
